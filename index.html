Classical AI vs Modern AI

Educational comparison of rule-based (Classical) AI used by CarePilot and data-driven (Modern) AI approaches. Conceptual only — no live machine-learning model is running in this prototype.

Classical AI (Used by CarePilot)

Classical AI relies on explicitly defined knowledge and symbolic reasoning. Core ideas include:

  • Rule-Based Systems & Expert Systems — knowledge captured as IF–THEN rules
  • Knowledge Representation & Knowledge Base — facts and rules stored in a readable form
  • Inference Engine — matches input against rules to produce conclusions
  • Decision Trees & Symbolic Reasoning
  • Explainable AI — the path from input to output can be shown step by step
How Classical AI works in CarePilot:
Input (symptoms, duration, severity) → Knowledge Base (keyword lists & priority rules) → Inference Engine (rule matching) → Output (provisional priority, reason, next steps, department)

Practical example from this project:
IF the symptom text contains a configured emergency-warning indicator (e.g. “chest pain”, “difficulty breathing”) OR severity is very high with very recent onset,
THEN assign HIGH PRIORITY, recommend Emergency Department, and show an emergency guidance alert.

Modern AI (Conceptual / Future)

Modern AI often learns patterns from large datasets. Key concepts:

  • Machine Learning & Deep Learning — models trained on data rather than hand-written rules
  • Neural Networks — layered architectures that approximate complex functions
  • Natural Language Processing (NLP) & Large Language Models (LLMs)
  • Generative AI, Predictive Analytics, Pattern Recognition
How Modern AI typically works (high level):
Input Data → Trained Model → Pattern Recognition / Inference → Generated Output

Hypothetical hospital applications (not implemented here): understanding free-text symptom descriptions, summarising patient-reported information, finding patterns in appropriately governed datasets, assisting with administrative documentation, or supporting staff information retrieval. These remain conceptual future enhancements.

Why Did We Choose Classical AI for CarePilot?
  • The project requires transparent decision rules that can be shown to evaluators and students.
  • The system must explain why a provisional category was assigned.
  • Rule-based reasoning is easier to demonstrate in an academic college project.
  • The knowledge base (keywords and rules) can be inspected and modified.
  • The inference process can be tested with predefined cases without training data.
  • It avoids falsely claiming that a machine-learning model has been trained or deployed.
  • It is suitable for demonstrating knowledge representation and explainable reasoning.

Limitations of this approach:

  • It cannot automatically learn new rules from experience.
  • It depends on predefined conditions and keyword lists.
  • It may not fully understand complex natural-language inputs.
  • It is not clinically validated and cannot replace professional medical assessment.

CarePilot – AI-Powered Hospital Assistance & Triage System

Project Objective

CarePilot is an educational hospital assistance and patient triage prototype designed to demonstrate how technology can support patient registration, provisional priority assessment, department recommendation, queue awareness, and general health information in a hospital setting.

Problem Statement

Hospital reception and triage can become congested. Patients may need guidance on where to go and how urgent their situation appears. Educational tools that illustrate structured symptom capture, transparent provisional categorisation, and clear next-step messaging can help students understand the value of organised triage support systems—while emphasising that real clinical decisions must always be made by qualified professionals.

Proposed Solution

A single-file web application that allows demo patient registration, rule-based provisional priority assessment with explanations, recommended next steps, department suggestions, queue visualisation, a rule-based educational chatbot, knowledge base, and basic analytics—all running offline in the browser with LocalStorage.

Main Features
  • Dashboard with live statistics and charts
  • Patient registration with automatic assessment
  • Provisional priority categories (High / Medium / Low Demo / Needs Human Review)
  • Explainable reasons and recommended next steps
  • Emergency warning system for configured warning signs
  • Department recommendation (demonstration rules)
  • Patient management (search, filter, edit, delete)
  • Queue management with status updates
  • CarePilot AI Health Assistant (rule-based educational chatbot)
  • Knowledge base on symptoms, departments, and triage concepts
  • Reports, analytics, and CSV export
  • Full LocalStorage persistence
How the System Works
  1. User registers a patient with name, age, gender, symptoms, duration, and reported severity.
  2. The system applies transparent demonstration rules to symptoms, duration, severity, and keyword patterns.
  3. A provisional priority, reason, next steps, and department suggestion are generated automatically.
  4. Emergency-style keywords trigger a highly visible alert recommending real emergency services.
  5. Records are stored in browser LocalStorage and appear on the dashboard, patient list, and queue.
  6. Staff can update status, edit, or delete demo records. Charts and counts refresh automatically.
Technologies Used

HTML5, CSS3, Vanilla JavaScript, Browser LocalStorage. No backend, no database server, no API keys required for core functionality. Single standalone file.

Limitations
  • Not a medical device and not clinically validated.
  • Rule-based logic only; no machine learning or live AI model.
  • Cannot diagnose, prescribe, or guarantee safety of any priority label.
  • Low Priority is labelled “Demo Only” and must never be interpreted as permission to delay care.
  • Data is fictional and stored only in the local browser.
  • Real hospital triage requires trained professionals and validated protocols.
Future Scope
  • Integration with a secure backend and authenticated hospital systems
  • Optional connection to a real medical-grade AI or clinical decision support API
  • Multi-user roles (reception, nurse, doctor)
  • Printable patient assessment summaries
  • Improved accessibility and multi-language support
⚠️
Important Disclaimer This is an educational college prototype. It must not be used for real patient care or clinical decision-making. Always consult qualified healthcare professionals and emergency services when needed.
